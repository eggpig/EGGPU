# 数据集与 E1–E6 实验冻结方案

版本：2026-11-04，selection/protocol v1。依据本会话用户要求冻结；本文件取代旧报告的数据集选择和实验组织，保留全部历史原始数据及证据 ID。**这次完成的是选图与实验协议，不是新一轮 GPU 实测。**

## 1. 决定与研究问题

主图集固定 **7 张、3 类：道路网络 RN、社交网络 SN、网页链接 WG**。它们都是 real-world graphs，real-world 不另列为与社交平行的类别。六张大图承担规模、平均度和显存压力覆盖；Epinions 保留为精确扩展函数完整任务与独立参考的中等规模锚点。选图不以现有胜负筛选，后续慢结果、OOM、超时均保留，不据此换图。

全文主线固定为：**连续图分析中，数据变化、函数依赖及物理共享关系决定维护和保留的代价；框架能否在给定资源下减少正确完成整段任务的时间。** 单次内核性能、缓存命中率、patch 字节数分别是解释指标，不能代替完整任务结论。

新论文组织为 E1 整体同资源比较、E2 固定工作强扩展、E3 D-Maintain、E4 C-Retain、E5 D×C 联合干预、E6 扩展函数的完整任务价值。历史 E5 中的应用材料迁入新 E6，联合消融归新 E5；原始路径和 ID 不改名。

### 3.3 输入和权重规则

保留来源声明的顶点全集，不按本次实际出现边重新删除孤立点；原 ID 按确定顺序映射为连续 ID，映射表入哈希。删除自环；同方向重复弧合并；无向源按唯一关系去重再生成两条方向弧；CSR 行内按目的 ID 排序。EP 的 E6 另建弱无向、无权、简单投影，记为 **EP-U**，不能与 EP 混用。LJ-U 同理。投影保留原顶点全集。

E1/E2 的 SSSP 和 E3–E5 的受控权重使用固定正整数1–16，固定种子20261104；无向关系的两条弧权重一致。对规范化端点键执行 SHA256，取摘要前8字节的大端整数，`w=1+(h mod 16)`；域字符串与端点文本格式写入 registry。旧历史权重若不同，保留原合同，不能无重测混入新表。生成权重表示受控算法负载，不声称来自实际社交强度或路长。

主表 PR 是全局无权 PageRank。E3–E5 标记 **WPR** 的格子才使用上述权重作为转移强度；这是受控测试，未把同一数值同时解释为实际最短路成本和实际影响强度。

## 4. 所有实验共享的测量合同

### 4.1 版本、资源与配置

1. 新主表绑定同一 EGGPU release、源码/DSO 指纹及确定的分派策略。优化单卡路径必须保留，并在计时前按能力、数值语义、设备数冻结分派；不能逐图选历史最快实现。
2. E1 单卡为一块卡对一块卡；八卡为八块卡对八块卡，CPU 核数、主机内存、NUMA、频率及互联记录相同。CPU–GPU 系统可以合法使用同等主机预算，不人为禁用 CPU 协作。
3. E2 固定分区执行后端，P=1/2/4/8。不能用 E1 的另一种优化单卡实现作为分区后端强扩展的 T1。
4. 静态执行编码和运行参数按能力预先冻结；E3–E5 固定 FP64 状态维护配置，不能把静态 u8 的空间收益混入 FP64 的维护消融。除干预因子外，算法开关、布局、主机复制策略全部相同。
5. 分区规则和种子固定；P 变化只按同一规则生成对应分区。记录每卡点/边/halo/通信量，保留倾斜结果。不按某图的计时挑分区。任何新支持缺口先报告，不静默换语义。

### 4.2 四个计时边界

- **共同输入准备**：原文件读取、解压、统一规范化单独记录；系统无关部分可在主比较计时外，但必须所有系统一致。
- **首次完整任务 T_first**：从相同、已在主机的规范化边数组输入开始，包含系统专有执行器/worker/MPI进程启动、CUDA上下文初始化、格式转换、压缩/分区、图对象创建、上传、计算、同步、输出恢复到统一 ID/类型及拥有独立生命周期的结果返回。共同测量控制进程可以预先启动，但不得仅让某个被测系统预建CUDA context、进程池或图状态；启动成本另列拆项仍计入T_first。已准备好的 Native CSR/分区不能只给 EGGPU 免费使用。
- **已准备完整调用 T_ready**：图已建且上一请求完成，从本次请求进入，到完整输出与必要的预算修剪完成。每次重新执行算法，不缓存答案。单独给出内核时间作解释。
- **整段任务 T_workflow**：首次初始化 + 全部提交/更新/维护 + 全部计算与依赖步骤 + 传输/输出 + 保留策略开销；最终销毁单列并同时给出包含销毁的总时间。不得只报告去掉重建的循环时间。

准备成本的摊销直接用实测前缀总时间，E1 固定前缀长度1/4/16，E4 给全轨迹；没有在观察窗口内交叉就报告“未达到盈亏平衡”。异步阶段的墙钟覆盖区间不直接加和，跨卡取关键路径；避免把嵌套计时重复计入。

输出验算在返回后的统一校验阶段完成，校验耗时独立记录；返回所必需的D2H、映射和结果物化在主计时内。所有正式重复都保存完整输出或无损压缩/内容寻址的等价可恢复副本。

### 4.3 语义与统计

BFS 返回全顶点距离（不可达哨兵统一）；SSSP 返回同样方向、权重和源点下的全距离。整数距离在可精确表示范围内要求一致，不可达集合必须一致。WCC 比较顶点划分而非任意组件标签数值。PR 固定 damping=0.85、均匀初值/teleport、统一 dangling 处理，验收真实L1不动点残差≤1e−6、概率和误差≤1e−6、相对独立参考的L1差≤1e−5；最大2000轮，达到上限仍不合格则记精度未通过。库内同名 tolerance 先校准为上述共同质量，不能只写“都用相同 tol”。PPR 不代替 PR。

BFS/SSSP 固定三源：有向图最大 SCC（并列用最小 canonical ID）内，按 `SHA256(source-domain, dataset-id, vertex-id)` 排序取前三个不同顶点；无向图在最大连通分量中取。若最大 SCC 不足三点，用最大 WCC 中非零出度点补齐并标记。源点只由拓扑决定，首次计时前保存；另有一个全图散列选择的任意源作可达性边界，不混入三源主统计。三源结果都报告；先逐源对独立重复取算术均值，再三源等权算术平均，最后求两个系统的时间比，不能只留最快源。

新测每个资格通过的完整配置固定十个独立进程重复；同一输入/轨迹种子对各变体配对，执行顺序在重复间平衡。冷任务每次从无图状态开始，热任务有完全相同预热前缀。保存均值、样本SD、95%CI、原始十次；历史n=3保持原样。均值区间采用Student-t，机制配对差/交互以每个配对块为样本；源点不能充当额外独立进程样本。CV>20%明确标为不稳定，不以当前CV决定停止或删重复。p95仅对足够长的请求序列报告，不拿十个进程均值冒充尾延迟分布。

超时合同：E1/E2 每个完整任务30分钟，E3–E6 每条完整轨迹/应用60分钟；系统专有准备计入T_first及其超时，单列仅指拆项展示，共同离线规范化另计。所有系统使用相同硬件限额。超时是删失数据，不能把上限当作真实耗时做加速比。OOM、不支持、错误、超时分别标记；报告完成覆盖率和可配对速度，不把未完成当无限加速。输出不合格时不纳入性能胜率。资源资格可以先做，不能据资格或速度删图；需要改协议时留正式版本差异，旧配置保留。

## 6. E1：整体性能与准备成本

固定算法 BFS、SSSP、WCC、PR，七图均进入计划。每个算法记录 T_first、T_ready；另测每图 `[BFS,SSSP,WCC,PR]×4` 的16请求静态多函数任务，BFS/SSSP按三源循环，保存前缀1/4/16的完整时间。这条固定轨迹的源出现次数为2/1/1，独立报告，不并入前述三源等权的单函数主统计。此处不加权重更新、不制造受限驻留，以回答系统基本竞争力与真实首次成本。

外部候选按已登记源码及真实能力进入：单卡优先 cuGraph、Gunrock、Grapin，并纳入 C²graph/CGgraph/HyTGraph 的适用语义格子；多卡优先 GUM、cuGraph 的真实多卡执行路线。igraph 用作独立参考和适用CPU路径，不把慢CPU自动当最强性能基线。所有适用且质量合格的已冻结实现都显示；突出其中最快已测外部均值，同时保留各基线明细。当前未复现的论文结果不能直接填进本机表。

为 C²graph 同时展示含压缩的首次/完整任务和已准备查询，避免准备成本被隐去。若作者实现只提供PPR/其他遍历，对全局PR记不适用。GUM 在当前硬件未启用原RWS路径时明确说明，可另列支持P2P硬件的复现，但不把不同机器数字拼在同一主表。

主图建议：一卡、八卡两个分面，每图四函数完整时间/相对最快外部；旁边独立的首次/准备后比值或准备占比。16请求任务画累计时间曲线，避免用一个几何平均掩盖准备收益和小图开销。小图EP及US负例保留。此实验支持系统层结论，**不能单独证明 D 或 C 的因果收益**。

## 7. E2：固定工作强扩展及退化原因

US/OR/IN/UK/TW，四算法，相同全图和三源/收敛标准，P=1/2/4/8。同一分区后端、数值语义和策略；仅按固定规则改变分区数。每个P同时记录首次与已准备完整时间、每卡峰值、边/点负载、跨卡真实流量、通信轮数、同步与控制开销。

主指标 `S_P=T_1/T_P`、`Eff_P=S_P/P`。若P1因容量或索引约束不成立，不能补造T1：该图报告可完成最小P和容量范围；`T_Pmin/T_P` 仅作为另标起点的补充，不叫1→8强扩展。E1优化单卡值可以虚线标注供用户选资源，不参与上述比值。

主图四函数曲线，所有图点与不单调部分保留；用US和OR/IN各一个时间拆解解释小frontier/同步开销与大工作量收益。TW承担容量边界。当前已有“PR单调、其他不一定”的结果保留，不预设新矩阵四函数都单调。此实验不以同时跑P倍独立任务代替同任务扩展；吞吐另图另名。

## 8. E3：D-Maintain 的收益范围

这里的 D 是 dependency-aware maintenance。当前严格范围为 Native FP64 权重版本的依赖维护、稀疏patch、独占转交/COW及旧读者安全；不是增量最短路，也不是通用拓扑插删引擎。更新后算法仍然完整执行。

### 8.1 三个控制组

| 组 | 行为 | 作用 |
|---|---|---|
| Rebuild | 新代图重建相关执行状态 | 解释粗粒度失效的代价，不作为唯一强对照 |
| Reuse+Full | 保留未变拓扑和合法状态，变化权重全量维护，正确保护旧读者 | 主要强内部对照，避免把所有收益归于“有缓存” |
| D-Maintain | 同样执行器，启用依赖选择、合法patch/转交/COW；SSSP匹配base时使用精确packet | 检验D的额外价值 |

外部系统如有合法更新API则使用；否则允许保持静态拓扑和最佳可用重建路径，完整计入成本，并标记API能力差异。外部比较只支持系统效果，内部三组承担因果归因。

### 8.2 固定而分层的因素

主密度扫描：US/IN/OR，P1，`ρ∈{0,10^-6,10^-4,10^-2,0.1,1}`，ρ为变化存储位置数/A。无向关系两条弧同步更新。每批从冻结位置集合将 `w` 改为 `1+(w mod16)`，保证非零更新实际改变数值。位置采用均匀散布与CSR行聚集两种；相同ρ比较实际位置数、触达行数、连续区间数。ρ=0和1不重复制造无意义的局部性差异。

每条轨迹20次提交，每次提交后执行 `[BFS,SSSP,WCC,WPR]`；BFS/WCC不依赖权重，WPR明确是加权PR。另有无权PR负控制，检查它不会因权重改变而错误更新无关状态。当前精确packet发现路径限SSSP；WPR仍需主机差分/摘要等工作，计入完整维护，不声称它也消除了全量发现。函数切换另设只读子面板：同一固定版本上每函数4次，共16请求，比较按函数分组与四函数交错；不跨越20次更新重排。每个请求键固定为(graph_id, version, function, source, parameters)，以免相同函数名字实际读到不同版本。

旧读者轴独立在IN/OR、ρ=10^-4测试：无旧读者、旧版本被一个合法lease持有到下一次更新完成；验证旧结果/旧权重仍有效。旧读者持有的是输入版本/视图，不以返回的独立结果向量冒充活跃lease。不能通过提前释放旧读者做出不合法的“原地更新加速”。多卡复核IN/OR在P8同样配置，另把同数量更新集中于一个分区与跨分区均匀分布比较，所有变体输入一致。

### 8.3 需要给出的证据

主指标是提交开始到全部新结果返回的时间，并拆提交校验/哈希、主机复制、布局维护、H2D/D2D、算法执行、输出。记录packet载荷与实际总线传输分别多少、共享与复制拓扑/权重字节、COW次数、峰值和旧版本数。当前主机提交可能仍全量哈希权重；不能只报几字节GPU补丁而隐藏O(A)主机开销。

主图：横轴ρ对数，纵轴完整时间比；第二分面用堆叠字节显示全量、patch、COW；旧读者和局部性作小分面。需要显示ρ=0的管理开销、ρ=1的补丁失效范围、旧读者导致的复制代价。得到的结论应是“在哪些变化/依赖条件下维护更便宜”，不预写“所有动态任务都更快”。

## 9. E4：C-Retain 的保留与重载

这里的 C 是 closure-aware retention，强调一组视图对物理对象的共同持有关系。该实验固定拓扑和权重、不做更新，D配置全组一致，以隔离保留决策。

固定图池US/OR/IN/UK。每图四函数 `[BFS,SSSP,WCC,WPR]` 各8次，共128请求；源点规则一致。三条轨迹使用完全相同的请求多集合：按图集中、图轮转交替、固定种子置换交错。保留历史窗口固定32，不把未来请求提供给在线策略。另做每图仅访问一次的无回访控制。

预算按每张卡的实际空闲可保留对象测定：`S_{g,d}` 为图g在设备d所需视图集合不含活跃工作区的实际物理驻留，`B_min,d=max_g S_{g,d}`，`B_all,d=Σ_g S_{g,d}`。固定逐卡向量 `B_d(β)=B_min,d+β(B_all,d−B_min,d)`，β取0/0.25/0.5/0.75/1；绝对字节向量在资格时生成并在所有内部策略间共用，不能各策略按自己的峰值归一化。图内共享去重计数，预算不是逻辑视图大小之和。若预算或峰值超过硬件能力，保留不可执行格子，不静默缩图。各图/视图的实际共享程度是记录的解释变量，本轮不把它冒充独立操纵的实验轴。

对照为 No-retention（无保留参照）、view-LRU、按共享组处理的closure-LRU、按逻辑大小评分的需求策略、C-Retain。所有策略均用实际物理占用判断是否达标，都保护活跃lease；view-LRU遇到撤销后释放0字节应继续尝试合法对象，不能人为让它提前失败。C使用现有历史需求与真实可释放量评分，不称未来恢复毫秒最优模型。统一分配器、trim时点和所有权判定。

记录完整128请求时间、每次返回时间、图/视图命中、重载H2D、实际释放字节、请求引发的维护路径及策略开销；分别登记受管驻留预算与NVML总显存峰值。当前预算在调用完成、结果独立持有后修剪，**不是任意时刻总显存硬上限**。

外部系统完整任务对照允许持久状态和最强合法缓存。在相同物理显存硬件预算下做系统比较；仅当能够执行同样的驻留合同才加入β扫描，不能用人为逐次销毁外部图来制造胜利。内部策略β实验与外部系统全驻留面板分开。

主图为预算–完整时间曲线，辅图为实际重载字节；再用一条真实请求轨迹显示“撤销了哪些视图→释放哪些物理数组→下一次为何命中/重载”。全驻留β=1、无回访是必要边界。C可能接近LRU或产生额外开销，应如实保留。

## 10. E5：D 与 C 的联合干预

固定IN/UK/OR图池，采用E4交错轨迹结构，并在每个图每次回访前提交权重更新。主要配置ρ=10^-4、均匀散布、β=0.25；ρ=0和β=1为负控制，每组一卡和八卡分开运行。每图8轮，每轮 `[BFS,SSSP,WCC,WPR]`，共96请求；顺序、更新位置、源、初始状态跨四组完全一致。

| 组合 | D | C |
|---|---|---|
| D0C0 | E3 Reuse+Full | closure-LRU |
| D1C0 | D-Maintain | closure-LRU |
| D0C1 | E3 Reuse+Full | C-Retain |
| D1C1 | D-Maintain | C-Retain |

此处D0/C0都是合理的强替代，并非同时关闭所有复用。其余主机共享、算法开关和编码完全相同。旧读者条件作为另外预登记的配对面板，不能只给某一组增加lease。

同时报告四组 T_workflow、维护H2D载荷、所有H2D/D2H总量、D2D、峰值、重载/patch/COW次数。交互定义 `I_T=T11−T10−T01+T00`，时间越小越好，因此负值表示超出加和的节省；字节同理。用完整配对重复估计CI，而不从四个无关均值捏造显著性。时间、维护字节、全部传输分别计算，不能互相代称。

机制链必须能从日志还原：C保留了哪个可维护版本/共享对象→下一次D选择patch而非全量准备→少传哪些字节→这部分是否足以影响完整时间。已有历史联合实验每次少8,129,200字节的是权重维护载荷；其完整时间交互CI跨零。该结论继续保留，不能因新设计写成已证实的时间协同。新结果可能证明交互，也可能只证明字节作用；论文结论按区间收缩。

主图四组完整时间及CI，下方四组维护/总传输两条不同指标；必要时一个交互区间图。它解释两机制的相互影响，不重画E3/E4所有扫描。

## 11. E6：扩展函数覆盖对完整任务的贡献

### 11.1 固定任务与图

主任务：**全图 Effective Size + Constraint → 排名选32个候选 → 32候选的精确 WF Closeness → 选一个节点 → 该节点 BFS + 全图 WCC → 完整输出。** 后一步真实消费前一步结果，候选不能预先算好放在计时外。主图EP-U、LJ-U；OR作为固定压力副面板，超时/容量失败也报告，不以其结果决定是否换图。

EP-U已知N=75,879，405,740无向关系，811,480存储弧；LJ-U须按冻结投影规则准备，不沿用文献未知投影的85.7M数值。ES/Constraint仍对全顶点计算，32候选只限制Closeness阶段的源集合，不把全图结构洞计算偷换成32点。

沿用现有工作流的确定规则：只保留ES与Constraint均有限的点；`q(x)=rint(x/10^-6)`，按q(ES)降序、q(Constraint)升序、canonical ID升序取前32，少于32则取全部。每个候选的WF closeness为 `r²/((N−1)·Σdist)`，r为可达的其他点数，r=0时为0。按量化后closeness降序和ID升序选winner。定义及舍入规则所有实现一致；完整候选表、winner、距离、WCC划分都校验。

全局数值验收为 `abs(error)≤1e−6+1e−5·abs(reference)`；WF closeness用 `1e−8+1e−5·abs(reference)`。此外量化排名/候选/winner必须一致，误差容忍不能掩盖实际不同的决策。若边界数值导致排名不一致，标为任务语义未通过并修复共同规则，不择优使用某一实现的候选。

这一流程是有网络分析/结构洞分析文献动机的受控分析任务，不声称是已获得的真实生产请求轨迹，也不据性能证明所选节点的社会学因果价值。现有应用证据出处见项目 `docs/APPLICATION_WORKFLOW_EVIDENCE_CN.md`；候选任务实际代码与测量见 `extended_workflow_20261101/v2` 和 `addon`，不是只读早期CPU版README。

### 11.2 必须增加的功能组消融

| 变体 | ES + Constraint | Candidate Closeness | BFS + WCC |
|---|---|---|---|
| A | 最强已资格外部实现/组合 | 最强已资格外部实现/组合 | 相同 EGGPU 核心 |
| B | EGGPU 扩展 | 与A相同外部 | 相同 EGGPU 核心 |
| C | 与A相同外部 | EGGPU 扩展 | 相同 EGGPU 核心 |
| D | EGGPU 扩展 | EGGPU 扩展 | 相同 EGGPU 核心 |

另列一个**从头到尾外部组合**，证明完整系统相对外部的实际位置。A–D用于控制变量，不能把A包装为独立外部系统。优先复用已测的 CuPy + direct pylibcugraph 等纯GPU组合；若有更强、语义一致的现成算法也纳入资格，CPU igraph仅在有依据的适用角色使用。不故意让外部逐阶段转Python对象、复制回CPU或放弃缓存。所有真实格式变换和跨实现交接都计时，并在阶段图中单列。

四组相同输入、四核心策略、数值规则、缓存合同与资源；固定足够驻留预算消除C逐图选胜的干扰。外部函数结果转入本系统所需的开销是功能组合的实际代价，但需要分别报告纯计算与交接，才能说明收益来自内核还是组合方式。

首要结果是第一次完整应用、相同任务再次完成的热应用、各阶段与交接耗时、峰值和最后输出一致性。每次都重新计算候选，禁止缓存上次答案。给出A→B、A→C以及D的完整时间变化；不把“多支持了若干API”当成实验证据。

### 11.3 多卡边界和覆盖范围

先在一卡完成四变体和外部完整对照，再对完整D在EP-U/LJ-U做1/2/4/8卡资源面板。结构洞函数复制整图、分配ego顶点；Closeness复制整图、分配source；BFS/WCC尾部固定在logical GPU0，保持现有应用路线。逐阶段标记模式，计入复制/最终合并，不称“全部函数统一分区、多卡能容纳超单卡大图”。以后若接入分区尾部，须另立整套固定配置，不能逐图择快。单卡装不下复制图时，多卡source/ego分配也不能消除该限制。

附一张函数语义/输出/SG与MG模式/本实验是否覆盖的矩阵，明确ES、Constraint、Closeness的结果证据覆盖了哪些扩展能力。BC、Efficiency、Hierarchy、LCC、K-core、SCC、MST、TC等未进入这个主任务的函数，不借此宣称全部在大图多卡上验证完毕；已有独立资格证据保留来源。

现有GrQc“Constraint→真实删点→残图WCC/全源Closeness”保留为历史补充，不让它变成新增主图。删点生成新拓扑也不冒充D的原位权重patch能力。

## 12. 落地顺序、图表分工与冻结约束

执行顺序：

1. 接入US/LJ/TW，核原文件校验和、规范化计数、ID映射和方向；核已有EP/OR/IN/UK输入回执。生成分区、源、权重与轨迹manifest并绑定哈希。这一步不比较性能。
2. 完成优化单卡路径与最新多卡release的语义分派资格，以及Gunrock/igraph PR共同质量证据链；登记外部源码revision/实际支持矩阵。
3. 跑E1完整同资源主矩阵与E2固定后端；不替换已发布历史测量。新表有完整新版本来源后才取代旧表。
4. 跑E3/E4有区分力的扫描，再E5配对四组合；复用已有测量只在输入/源码/参数/边界完全相同时允许，不能以相近图名拼接。
5. E6先完成EP-U四变体和全外部，再LJ-U；OR按已登记压力面板记录。按超时合同报告，不据结果改任务或选图。

正文信息分布：E1主性能与完整任务占最大面积；E2一组扩展曲线；E3/E4各一张机制收益图；E5四格联合干预；E6依赖任务与功能组消融。重复的底层指标进可复核artifact，不用六组都堆同一套四算法柱状图。

本次不自动下载十亿边图、不启动GPU、不修改业务源码。冻结文件及registry是下一轮数据准备与实验的执行依据。选图之后只允许补元数据、合法修复输入/实现、记录正式协议修订；任何修订都写原因、影响范围、旧数据如何保留，禁止因优势不明显而静默换图/换权重/换源/换任务。

本协议定义了应测的对照，不代表它们全部已有可直接运行的launcher。Reuse+Full、closure-LRU、严格物理预算和E6四变体须逐项与源码能力对照，缺少的控制路径先实现并资格化，再进入计时；不能用名字相近的历史开关顶替。
