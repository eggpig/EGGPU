| EGMGPU | worker、gang、分区通信、宽函数调度 | 合入显式公共路由与原生 runtime；分区和复制式分别记录 |

## 函数与执行模式

| 函数组 | 单卡源码 | 多卡执行方式 | 本次统一 Session |
|---|---|---|---|
| BFS / 无权最短路 | 有 | owner 分区协作 | native / arena |
| Dijkstra / SSSP | 有 | owner 分区协作 | native / arena，非负权完整距离 |
| Bellman–Ford | 有，保留负权路径接口与负环检查 | 单卡或请求并行 | 公开函数入口；未接入统一 Session 的非负 SSSP |
| PageRank / Weighted PR | 有 | owner 分区协作 | native PR/WPR，arena WPR |
| WCC | 有 | owner 分区协作 | native，弱连通投影须正确 |
| Betweenness、Closeness | 有 | 各卡完整图，按源点分工 | 宽函数显式入口 |
| EffectiveSize、Efficiency、Constraint、Hierarchy | 有 | 复制图或子集任务分工 | 宽函数显式入口 |
| LCC、SCC、KCore、MST/MSF | 有 | 单卡或不同请求分派到不同卡 | 宽函数显式入口 |
| Triangle Count 扩展 | 有 | owner 唯一分工，forward CSR 各卡复制 | 独立显式服务 |

稳定公开接口为 16 个名字，包含语义相近的路径函数；接口数量不等于独立图问题数量。分区协作、复制图任务并行、请求并行应分别统计。原有 4 核心分区路由及 6 个复制式路由的资格文件绑定其具体部署；本树不携带可冒用为新部署通过证明的旧资格索引。

## 机制实际统一了什么

公共请求以图语义版本为核心，而不是以“显存中现在有哪些数组”识别输入。一个合法物理准备可以创建 CSR、incoming 视图或更新派生量，但不改变逻辑快照；真正的数据提交会改变快照。此区别同时用于单卡懒物化与多卡不可变快照，避免把缓存更新误判为数据更新。

共同合同覆盖：图身份和节点顺序、算子读依赖、私有写状态、完成边界、独立输出、close 行为及能力说明。单卡更新在本地 journal 中推进；多卡固定拓扑权重更新发布新 manifest 并保留旧快照。相同的请求层连接两种执行器，所有权、预算和执行算法仍由各自后端管理。

后续原子算子推进可以围绕依赖集合、有效版本、恢复代价与 workspace 峰值开展；本版已把请求合法性和生命周期接到真实执行调用。它尚未实现自动跨算法 kernel 融合或跨设备共享同一物理 CSR，论文应对应实际干预项和实验。

## 同步与维护建议

先在上游固定提交建立工作分支，应用本交付补丁，再在新机进行资格运行。CPU 改动、GPU 核心、资源控制、宽函数路由与测试文档可按审阅顺序拆成后续提交；无需把历史目录推送到仓库。上游未来更新时，以本树的 CPU 兼容回归和 GPU 资格入口检查受影响路径。外部实验数据和测量结果独立维护，源码树只保留小型可生成的资格样例。
